## معیارهای پذیرش

- [x] صفحه «مسیرهای پروازی» در ورود اولیه فقط راهنما، دکمه افزودن، تب‌ها و فهرست/حالت خالی را نشان دهد.
- [x] با کلیک «افزودن مسیر جدید» فرم تعریف مسیر باز شود و با «انصراف» بسته شود.
- [x] فرم مسیر در چیدمان دو ستونه، ترتیب فیلدها و دکمه تمام‌عرض مطابق تصاویر مرجع باشد و همچنان از API واقعی زمان‌بندی استفاده کند.
- [x] صفحه «صندلی‌های تخصیصی» ابتدا مسیرها، فیلتر مبدأ/مقصد و جزئیات ظرفیت واقعی هر مسیر را نشان دهد.
- [x] فرم درخواست صندلی فقط پس از انتخاب مسیر باز شود و دوره، روزهای هفته، تاریخ شروع، روش پرداخت و جمع واقعی را نمایش دهد.
- [x] منوی پروفایل آژانس نام، شناسه واقعی، اعتبار قابل استفاده و چهار میان‌بر مرجع را داشته باشد.
- [x] خرید بلیط آژانس شمارنده مستقل بزرگسال، کودک و نوزاد با دکمه تأیید داشته باشد و همین ترکیب را به نتایج ارسال کند.
- [x] باکس خرید بلیط در موبایل به‌صورت فشرده دو ردیفی نمایش داده شود، عبارت «یک طرفه» خوانا باشد و این صفحه فوتر نداشته باشد.
- [x] تب‌های صندلی تخصیصی در موبایل به‌صورت یک ردیف قابل پیمایش، با شمارنده مجزا و حالت فعال واضح نمایش داده شوند.
- [x] تقویم قیمتی نتایج دارای کنترل قبلی/بعدی، بازه قابل مشاهده و ارزان‌ترین روز واقعی باشد.
- [x] مرتب‌سازی نتایج گزینه‌های «پیشنهاد بلوجت»، «سریع‌ترین» و «زودترین پرواز» را مطابق مرجع نشان دهد.
- [x] «ویرایش جستجو» در نتایج، فیلدهای تاریخ، تعداد مسافر و کلاس را در یک ردیف فشرده نشان دهد و شمارنده مسافر در پاپ‌اور باز شود.
- [x] تمام داده‌های کسب‌وکار از API موجود/گسترش واقعی آن بیاید و هیچ داده نمایشی ثابت اضافه نشود.
- [x] تست‌های واحد/یکپارچه مرتبط و بررسی بصری دسکتاپ و موبایل پاس شوند.
