# هماهنگی کلاس بلیط و انتخاب صندلی

## هدف

کلاس کابین و کد کلاس نرخی خریداری‌شده باید بخشی از snapshot رزرو باشند و در تمام نمایش‌های بلیط/رسید قابل مشاهده بمانند. انتخاب صندلی نیز فقط از کابین همان رزرو و فقط از صندلی‌های آزاد مجاز است.

## معیارهای پذیرش

- [x] `BookingDetail` علاوه بر `cabin`، مقدار nullable `fareClassCode` را برمی‌گرداند.
- [x] بلیط مشتری، مدیریت رزرو و فهرست فروش/بلیط آژانس، کلاس کابین و کد کلاس نرخی موجود را نمایش می‌دهند.
- [x] نقشه صندلی، صندلی‌های کابین‌های دیگر را غیرفعال می‌کند.
- [x] صندلی فروخته‌شده یا رزروشده در رابط غیرفعال است.
- [x] سرور در لحظه ایجاد رزرو، تعلق صندلی به کابین خریداری‌شده و آزاد بودن آن را مجدداً و به‌صورت تراکنشی کنترل می‌کند.
- [x] تست رگرسیون برای نمایش کلاس و عدم امکان انتخاب صندلی کابین دیگر/صندلی اشغال‌شده وجود دارد.
- [x] در انتخاب مبدا/مقصد، تمام فرودگاه‌های همان شهرِ سمت دیگر حذف می‌شوند؛ برای نمونه انتخاب THR، فرودگاه IKA را نیز از مقصد حذف می‌کند.
- [x] جزئیات مسیر، مبدا را به مقصد نمایش می‌دهد و در نمایش عمودی جهت حرکت از گره مبدا به گره مقصد مشخص است.
- [x] تعریف فیزیکی MD-80 در دیتابیس با نقشه رابط یکسان است: ردیف‌های ۳ تا ۶ فرست، ۷ تا ۱۱ بیزینس و ۱۲ تا ۳۲ اکونومی؛ بنابراین صندلی 4E برای رزرو فرست معتبر است.
- [x] هیچ کلاس، قیمت، ظرفیت یا صندلی جایگزین در مرورگر حدس زده نمی‌شود و پاسخ سرور منبع نهایی است.
