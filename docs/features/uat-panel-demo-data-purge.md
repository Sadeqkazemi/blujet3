# پاک‌سازی داده‌های نمایشی پنل‌های UAT

## هدف

در محیط سندباکس، همه رکوردهای عملیاتی و محتوای نمایشی قدیمی از پنل مشتری، آژانس و مدیریت حذف شوند. فقط حساب‌های فنی لازم برای ورود به UAT و داده‌های مرجع/تنظیمات ضروری حفظ می‌شوند.

## معیارهای پذیرش

- نام مسافر نمونه، پیشنهاد جست‌وجوی نمونه و placeholder شامل اطلاعات شخصی از UI زمان اجرا حذف شده باشد.
- داشبورد رئیس هیئت‌مدیره وضعیت سرویس را فقط از API نمایش دهد و در نبود داده، Empty State صادقانه نشان دهد.
- صفحه کارکنان IT ماتریس نقش و حوزه دسترسی ثابت و ساختگی نمایش ندهد؛ داده‌های کارکنان و مجوزها فقط از API خوانده شوند.
- اسکریپت پاک‌سازی در حالت پیش‌فرض فقط Dry-run و شمارش جدول‌ها را گزارش کند.
- اجرای واقعی فقط با `NODE_ENV=production`، فعال بودن `AUTH_SANDBOX_ENABLED`، عبارت تأیید صریح و شناسه بکاپ پذیرفته شود.
- تمام جدول‌های عملیاتی، شامل پرواز، رزرو، مسافر، آژانس، تراکنش، پیام، گزارش، لاگ و محتوای نمایشی پاک شوند.
- اطلاعات باشگاه مشتریان شامل اعضا، موجودی و گردش امتیاز، درخواست‌های کارت و همچنین گردش کیف پول پاک شوند؛ قواعد سطوح باشگاه به‌عنوان تنظیمات سامانه حفظ شوند.
- جداول مرجع و تنظیمات ضروری حفظ شوند: فرودگاه‌ها، نقشه صندلی، مجوزها، قواعد و تنظیمات سامانه.
- از جدول کاربران فقط Super Admin و حساب‌های ورود با پیشوندهای `uat.` و `panel.` حفظ شوند.
- کش Redis پس از اجرای پاک‌سازی خالی شود تا رکورد قدیمی در UI باقی نماند.
- استقرار، پیش از حذف یک بکاپ PostgreSQL با دسترسی root-only بسازد و با sentinel فقط یک بار پاک‌سازی را اجرا کند.
- Seed توسعه و E2E تغییر نکند و همچنان فقط در محیط غیر production قابل اجرا باشد.
- تست‌های Backend و Frontend و Build موفق باشند.

## خارج از دامنه

- تغییر API یا Schema دیتابیس
- حذف حساب‌های ورود UAT، Super Admin یا تنظیمات زیرساختی
- پاک‌سازی محیطی غیر از سرور UAT تأییدشده
